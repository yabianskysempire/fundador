Dataview en Obsidian para principiantes: consultas simples para ver tus proyectos, clientes y tareas

Qué es Dataview y para qué sirve

Dataview es un plugin de la comunidad que te permite consultar tus notas como si fueran una pequeña base de datos. Escribes una consulta dentro de una nota y Obsidian muestra una lista, una tabla o un conjunto de tareas con la información de otras notas.

La idea clave: tus datos siguen viviendo en las notas. La consulta es solo una vista que se arma sola a partir de ellas.

Cómo instalar el plugin

  1. Abre Ajustes (el ícono del engranaje).
  2. Entra en Complementos de la comunidad.
  3. Si aparece el Modo restringido, desactívalo para poder usar plugins de la comunidad.
  4. Pulsa Explorar y busca "Dataview".
  5. Pulsa Instalar y después Activar.

Los nombres exactos de los menús pueden variar un poco según tu versión de Obsidian y tu idioma.

Paso previo: ponle datos a tus notas

Dataview solo puede mostrar lo que encuentra en tus notas. La forma más simple es usar propiedades al inicio de la nota (frontmatter). Por ejemplo, una nota de proyecto:

---
tipo: proyecto
estado: activo
cliente: Estudio Norte
entrega: 2025-07-15
---

Y una nota de cliente:

---
tipo: cliente
etapa: propuesta
---

También puedes escribir campos dentro del texto con dos puntos dobles, por ejemplo responsable:: Ana. Para empezar, quédate con las propiedades al inicio.

Tres consejos para que no falle nada:

  • Usa nombres simples, en minúsculas y sin espacios (estado, entrega, etapa).
  • Escribe las fechas como AAAA-MM-DD.
  • Sé consistente: si en un proyecto escribes activo, no uses Activo o en curso en otro para decir lo mismo.

Tu primera consulta: LIST

Una consulta se escribe en un bloque de código con la palabra dataview. La más simple es una lista de notas de una carpeta:

LIST
FROM "Proyectos"

Esto muestra un enlace a cada nota de la carpeta Proyectos. También puedes filtrar por etiqueta con FROM #proyecto, o añadir una condición con WHERE:

LIST
FROM "Proyectos"
WHERE estado = "activo"

TABLE: ver varias columnas a la vez

TABLE es la más útil para el día a día porque muestra varios campos juntos:

TABLE cliente AS "Cliente", entrega AS "Entrega"
FROM "Proyectos"
WHERE estado = "activo"
SORT entrega ASC

Qué hace cada línea:

  • TABLE define las columnas. AS les pone el nombre que quieras.
  • FROM dice de dónde leer las notas (carpeta o etiqueta).
  • WHERE filtra.
  • SORT ordena (ASC de menor a mayor, DESC al revés).

Si no quieres la columna con el nombre del archivo, usa TABLE WITHOUT ID y agrega file.link como columna:

TABLE WITHOUT ID file.link AS "Proyecto", cliente AS "Cliente", entrega AS "Entrega"
FROM "Proyectos"
WHERE estado = "activo"

TASK: todas tus tareas en un solo lugar

TASK busca tareas (las líneas que empiezan con - [ ]) en tus notas y las junta en una vista:

TASK
FROM "Proyectos"
WHERE !completed

!completed significa "que no esté completada". Así ves todas las tareas pendientes de todos tus proyectos sin abrir cada nota. Si marcas una tarea desde la consulta, se actualiza en la nota original.

Ejemplos listos para copiar

Cambia los nombres de carpetas y campos por los tuyos.

1. Proyectos activos ordenados por fecha de entrega

TABLE WITHOUT ID file.link AS "Proyecto", cliente AS "Cliente", entrega AS "Entrega"
FROM "Proyectos"
WHERE estado = "activo"
SORT entrega ASC

2. Entregas de los próximos 7 días

TABLE WITHOUT ID file.link AS "Proyecto", entrega AS "Entrega"
FROM "Proyectos"
WHERE entrega >= date(today) AND entrega <= date(today) + dur(7 days)
SORT entrega ASC

3. Clientes agrupados por etapa (un pipeline simple)

Si todavía no tienes notas de clientes con etapas, la guía para armar un CRM gratis en Obsidian explica cómo organizarlas.

TABLE WITHOUT ID etapa AS "Etapa", rows.file.link AS "Clientes"
FROM "Clientes"
GROUP BY etapa

4. Tareas pendientes agrupadas por nota

TASK
FROM "Proyectos"
WHERE !completed
GROUP BY file.link

5. Tareas con fecha vencida

Escribe tus tareas con un campo de fecha, por ejemplo:

- [ ] Enviar propuesta [vence:: 2025-06-10]

Y usa esta consulta:

TASK
WHERE !completed AND vence AND vence < date(today)

6. Las 5 notas de clientes modificadas más recientemente

TABLE WITHOUT ID file.link AS "Cliente", file.mtime AS "Última edición"
FROM "Clientes"
SORT file.mtime DESC
LIMIT 5

Errores comunes y cómo resolverlos

  • La consulta se ve como texto y no como resultado. Revisa que el bloque empiece con tres comillas invertidas y la palabra dataview, y que el plugin esté activado.
  • La tabla sale vacía. Casi siempre es el nombre de la carpeta, una comilla mal puesta o un valor escrito distinto (activo frente a Activo).
  • Las fechas no se comparan bien. Comprueba que estén en formato AAAA-MM-DD.
  • Un campo no aparece. Verifica que el nombre en la consulta sea idéntico al de la propiedad.

Si algo no funciona, simplifica: empieza con LIST FROM "Carpeta", confirma que ves resultados y ve agregando una condición a la vez.

Cómo seguir desde aquí

Un buen plan para esta semana:

  1. Elige una sola vista que hoy armes a mano (por ejemplo, proyectos activos).
  2. Agrega las propiedades necesarias a tus notas existentes.
  3. Crea una nota llamada "Panel" y pega ahí la consulta.
  4. Cuando funcione, añade una segunda vista, como las tareas vencidas.

Con dos o tres consultas en una nota de inicio ya tienes un panel que se actualiza solo. Antes de usar los ejemplos con información real, pruébalos en una bóveda de prueba para ver cómo se comportan con tus carpetas y campos.
